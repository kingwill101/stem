# Dart 3.13 upgrade and adoption guide

This guide covers developer-facing changes from Dart 3.9 through 3.13, with
special attention to Stem's workers, workflows, code generation, and adapters.
It summarizes the releases rather than duplicating every compiler bug fix.
The [SDK changelog][changelog] is the complete reference.

## Baseline

- Package language/SDK minimum: `>=3.13.0 <4.0.0`.
- Primary constructors are **stable in Dart 3.13**. No experiment flag is needed.
- The local validation toolchain is Dart 3.13.1 with Flutter 3.47.1.
- The latest stable patch checked for this guide is **3.13.3**, released
  September 1, 2026. Prefer that patch for new toolchain installations,
  particularly when cross-compiling applications with native build hooks.
- Flutter bundles its own Dart SDK. Use a Flutter release with Dart 3.13 or
  newer; upgrading an unrelated standalone Dart binary does not upgrade Flutter.

The installed SDK supplies the compiler, tools, and libraries. Each package's
SDK lower bound also selects its default **language version**. Installing Dart
3.13 while retaining a 3.12 lower bound does not enable primary constructors
in that package.

Raising the minimum drops support for Dart 3.12 and older consumers. It is a
compatibility change, not merely a developer-tool preference.

## Language changes by release

| Release | Stable changes | Relevance to Stem |
| --- | --- | --- |
| [3.9][release39] | Flow analysis assumes sound null safety for promotion, reachability, and definite assignment. | More precise analysis can expose dead or redundant code. |
| [3.10][release310] | Dot shorthands for contextually inferred enum values, static members, and constructors. Generator function return-type inference avoids spurious nullability. | Shorter typed configuration; check inferred types in `sync*` and `async*` code. |
| [3.11][release311] | No new language syntax. Analyzer/editor support for dot shorthands improved. | Tooling improvements, not a separate syntax migration. |
| [3.12][release312] | Private named initializing formals: `Options({required this._limit})` exposes `limit:` to callers. | Removes repeated private-field initialization boilerplate. Primary constructors were only experimental in this release. |
| [3.13][release313] | Primary constructors, declaring parameters, concise `new`/`factory` constructor declarations, and semicolon bodies for empty class-like declarations. A promotion-soundness fix also applies. | Simplifies suitable data classes without changing their public call sites. |

Records, patterns, switch expressions, and class modifiers predate this window
(Dart 3.0). Null-aware collection elements arrived in Dart 3.8. They remain useful,
but should not be described as new Dart 3.13 features.

## Primary constructors

Before:

```dart
class StepIdentity {
  const StepIdentity({required this.runId, required this.step});

  final String runId;
  final String step;
}
```

With Dart 3.13:

```dart
class const StepIdentity({
  required final String runId,
  required final String step,
});
```

The call site remains unchanged:

```dart
const identity = StepIdentity(runId: 'run-1', step: 'charge');
```

Important details:

- `final` and `var` parameters declare fields. A plain parameter does **not**
  automatically become a field.
- `const` goes before the class name in a constant primary constructor.
- Named/private primary constructors and super parameters are supported.
- A `this` block supplies an initializer list or constructor body when needed.
- Private named declaring parameters expose an unprefixed public argument:
  `class Options({required final int _limit})` accepts `Options(limit: 3)`.
- Enhanced enums can use primary constructors; enum constructors are
  implicitly constant.
- Concise in-body declarations such as `new(...)`, `new named(...)`, and
  `factory named(...)` are available independently of a primary constructor.

This is **not automatic data-class generation**: equality, hashing, `copyWith`,
JSON conversion, and workflow persistence are not generated by this syntax.
Preserve constructor names, defaults, field mutability, const behavior,
validation, and documentation when refactoring.

Review the initializer/body scoping rules and restrictions before converting
complex classes. In particular, a class with a primary constructor cannot also
have unrelated non-redirecting generative constructors. `final`/`var` parameter
modifiers are reserved for declaring parameters in primary constructors, rather
than ordinary function or in-body constructor parameters.

See the [primary constructor documentation][primary] and
[design explanation][primary-design].

## Libraries, tools, and platform changes

### Dart 3.9

- Analyzer CLI operations use the AOT analysis-server snapshot; a
  `--no-use-aot-snapshot` fallback exists for diagnosis.
- New lint rules include `switch_on_type` and `unnecessary_unawaited`.
- Git dependencies can select compatible version tags using `tag_pattern`.
- A root package's Flutter upper-bound constraint is enforced for the new
  language version. Be careful when adding Flutter constraints to a workspace.
- The CLI build preview moved to `dart build cli --target=...`.
- Native cross-compilation gained Linux ARM32 and RV64GC targets.
- DDC cancels outstanding asynchronous work from an earlier hot-restart
  generation, including JavaScript promise conversions.
- The Dart/Flutter MCP server became stable.

### Dart 3.10

- `Future.syncValue` provides a typed already-computed future value.
- Analyzer plugins gained the supported diagnostics/fixes/assists integration
  for editors and command-line analysis.
- Native build hooks/code assets became stable.
- The command-line frontend and VM executable were separated (`dart` and
  `dartvm`). The SDK stopped shipping an ia32 development toolchain.
- `Uri.parseIPv4Address` became stricter, including rejecting leading zeros,
  and gained substring parsing arguments.
- Granular deprecation annotations identify extending, implementing,
  subclassing, mixing in, or instantiating an API.
- `IOOverrides` became an abstract base class; custom implementations must
  follow the new class-modifier rules.
- JS interop added `JSArray.add`, typed-array and wrapper improvements, and
  stricter checks. Wasm migration away from legacy JS interop continued.

### Dart 3.11

- Pub workspaces support glob patterns; `dart pub cache gc` was added.
- `dart pub publish --dry-run` supports `--ignore-warnings`.
- `dart pub cache repair` focuses on the current project's lockfile by default;
  `--all` requests the wider repair.
- Analyzer plugin entrypoints can be cached as AOT snapshots. Analysis
  performance, dot-shorthand assistance, and format-on-type support improved.
- `simplify_variable_pattern` was added; several lower-value lint rules were
  deprecated.
- `dart:io` gained Windows Unix-domain socket support, with platform limits.
- JS interop gained `JSSymbol` APIs.
- Wasm no longer accepts `dart:js_util` / `package:js/js_util.dart`, and
  `dart.library.js_util` is no longer a supported Wasm conditional-import key.

### Dart 3.12

- VM regular expressions gained modifier spans and duplicate named captures.
- JS interop gained JavaScript iteration-protocol types and Dart
  iterable/iterator conversions, plus stricter wrapper conversion checks.
- The `isA` extension moved; code referring to its extension by name or through
  `show`/`hide` clauses needs attention.
- Wasm deferred-loader embedding APIs changed, including batched module loading.
- Pub gained Git LFS support and additional `@` package/version syntax.
- The analyzer gained `simple_directive_paths` and improved fixes for private
  named initializing formals.
- Primary constructors were available as an experiment, not a production
  language baseline at this version.

### Dart 3.13

Core APIs:

- `Future.pause` for a delay without a callback.
- `List.unmodifiableOf` and `Map.unmodifiableOf` with better type inference.
- `int.trailingZeroBitCount` and `int.oneBitCount`. Their bit width differs:
  full 64-bit representation on native platforms, low 32 bits on the web.
- File access/modification timestamps preserve microseconds rather than
  truncating to milliseconds.
- `InterfaceAddress` exposes network prefix/broadcast information.
  `NetworkInterface.addresses` now returns `List<InterfaceAddress>`.
- `InternetAddress.lookup` rejects previously accepted nonstandard IPv4 forms;
  cookie-date parsing again follows the permissive RFC algorithm.
- `JSFunction` and `JSExportedDartFunction` are generic;
  `JSObject.getPrototypeOf` was added.
- Advanced native isolate APIs include static `Isolate.create` and
  `Isolate.pinToCurrentThread`, plus instance `runSync`, `shutdownSync`,
  `runEventLoopSync`, `handleEvent`, `onEvent`, and
  `isPinnedToCurrentThread`. These are not drop-in replacements for the
  asynchronous worker pool.

Tools and runtime:

- The formatter separates import sections and improves call-chain, parameter,
  cast/type-test, and guarded-pattern layout. Several changes activate only at
  language version 3.13; formatting does not itself convert constructors.
- New lint rules include `async_return_with_no_await`,
  `empty_container_bodies`, `initialize_in_field_declaration`,
  `unnecessary_const_in_enum_constructor`,
  `unnecessary_primary_constructor_body`,
  `unnecessary_type_name_in_constructor`, and `use_declaring_parameters`.
  The `use_primary_constructors` lint is experimental even though the
  language feature is stable.
- `no_raw_types` and `no_dynamic_casts` provide lint replacements for the
  corresponding strict analyzer options. Do not disable existing checks without
  confirming equivalent coverage.
- Editor support includes inline debug values, widget-preview metadata, and
  connecting the analysis server to the Dart Tooling Daemon.
- Pub adds workspace JSON listing, cache preloading from package archives, and
  an internal fast resolution check.
- `dart build cli` adds target OS/architecture cross-compilation flags.
- Native `@RecordUse`/link-hook support can remove unused native code when the
  dependency and toolchain participate. Bumping Stem's SDK alone does not
  guarantee smaller SQLite binaries.
- Wasm deferred loading is a **preview**, enabled through the compiler flag
  `--enable-deferred-loading` and an appropriate embedder loader.
- Dynamic module linking remains experimental, not a new stable workflow
  deployment mechanism.
- Pub.dev/dartdoc support richer callouts and `{@example}` snippets sourced
  from example files.
- The native runtime improves memory safety and removes built-in fallback TLS
  root certificates. Deployments must provide system or explicitly configured
  trusted certificates.
- Custom C embedders have new isolate thread-ownership functions and a
  microsecond-based `Dart_FileModifiedCallback` contract.

### Migration-relevant patches

- 3.9.x fixed ARM32 compilation, tag-resolution stability, DDC issues, and
  workspace-example resolution (`pub get --example` in 3.9.4).
- 3.10.x and 3.11.x include dot-shorthand analyzer/compiler fixes, Windows CLI
  fixes, Wasm/typed-data fixes, and native-build-hook coverage fixes.
- 3.13.1 fixes several Wasm compiler crashes and a closure `hashCode` issue.
- 3.13.2 fixes primary-constructor enum formatting, Wasm/`record_use` compiler
  problems, and deprecates the legacy analyzer plugin system.
- 3.13.3 fixes incorrect Windows-to-Linux native-code cross-compilation with
  build hooks. Use this patch for that build path.

## What to adopt in Stem

1. **Baseline first:** align manifests, examples, docs, formatter output, and
   CI. Keep dependency/package-version updates separate unless required.
2. **Primary constructors selectively:** small immutable descriptors and DTOs
   are good candidates. Keep complex lifecycle classes explicit where that
   improves reviewability. Verify code generation before converting ORM models;
   regenerate generated files instead of hand-modernizing them.
3. **Typed immutable copies:** consider `unmodifiableOf` at registry/snapshot
   boundaries where it removes weak inference or repeated type arguments.
4. **Dot shorthands where context is obvious:** useful for typed enums/options,
   but retain explicit names in ambiguous public examples.
5. **Local delays only:** `Future.pause` may replace ordinary local delays.
   **Never replace durable workflow sleeps or retry scheduling with it.**
   Likewise, replacing `async` code with `Future.syncValue` must preserve
   exception timing and completion semantics, not just the return type.
6. **Keep the explicit workspace list for now:** `packages/*` would also select
   the intentionally auxiliary dashboard, and repository scripts need glob-aware
   discovery before changing that configuration.
7. **Treat isolate control, Wasm loaders, and native tree-shaking separately:**
   they need platform-specific design, measurements, and tests rather than a
   mechanical migration.

The SDK upgrade does not enable experiment flags or broadly rewrite production
constructors. The compiler-backed builder fixture uses primary-constructor DTOs
to verify this syntax at an actual generated-code boundary.

## Checks for this repository

- Run `flutter pub get` for the mixed Dart/Flutter workspace.
- Run the same quality command as CI:
  `dart run repodoc/bin/repodoc.dart quality:dart --include-flutter --workspace-only`.
- Run builder tests, including the real consumer compilation fixture.
- Run worker/workflow, SQLite native-hook/restart, adapter, and Flutter tests.
- Keep the portable JavaScript compile check in CI.
- Check container trust stores: current slim runtime Dockerfiles explicitly
  install `ca-certificates`; do not disable TLS verification to work around
  missing roots.
- Audit explicit `NetworkInterface`/`IOOverrides` implementations, legacy JS
  imports, and timestamp assertions when adding or updating integrations.
